# Source explanations

Enable `compiler.Options.Explain` when compiling, then query the resulting snapshot through the public SDK:

```go
options.Explain = true
result, err := compiler.Compile(ctx, options)
if err != nil {
    return err
}
explanation, err := result.Explain(compiler.ExplainQuery{
    Symbol: "example.com/service.User.Name",
})
if err != nil {
    return err
}
return json.NewEncoder(output).Encode(explanation)
```

The same query accepts a fully qualified handler or projected named type. Set `Response: "201"` together with a handler symbol to select that final response across its request conditions. Response keys are exact; a missing response is an error with guidance to inspect the handler's unresolved diagnostics. This API describes compiled candidates. Runtime route selection, overrides, and application authorization remain separate steps.

## Reading the evidence

- `source` identifies the physical Go declaration from the compilation's frozen source snapshot. Imported DTOs use module-relative source identities, and instantiated generic fields refer to their original declarations. Promoted embedded fields retain their declaring type. Anonymous nested fields share the enclosing type's metadata identity and are distinguished by physical position and wire name in that type's origins.
- `uses` associates a payload with its handler, neutral effect kind, direction, media type, status or parameter location, and frontend rule. Conditional uses retain `source.when`. Bodyless commits have a status and source without a payload Schema.
- `origins` gives the actual selected Go field/type, instantiated Go type, wire name, presence, and Schema. These facts use the codec that participated in compilation; fields excluded by that codec are not invented. A known source-root field with no selected projection returns empty uses and explicit guidance. Arbitrary dependency symbols without captured evidence are not treated as verified contracts.
- `rules` lists the rules actually used. `go.types` and the codec name describe projection facts; `openapi.TypeMapper[index]` and `codec.ProjectType` identify explicit centralized representations. Indices use the original mapper registration order. Custom rules must remain deterministic as required by the adapter SDK.
- `declarations` preserves descriptions, parsed JSON values, and their source. `implementation: "not-proven"` means the declaration is not evidence of enforcement. The projected Schema may include a declared minimum, required field, or enum while business enforcement remains unverified.
- `operation` preserves the complete handler template. Response queries return `responses` with each applicable condition and the final contract. `components` resolves references in these final contracts; each payload use also includes its own projection components.
- `transformed: true` distinguishes the payload projection from the final wrapped response. Field origins describe the payload before wrapping; their wire names are not asserted to be paths in the transformed output. `provided: true` means the frontend supplied a Schema without Go field projection.
- `diagnostics` retains handler diagnostics, including other conditional paths with their original scope. `guidance` includes their centralized remediation instructions. An explanation does not suppress a diagnostic or make a failing candidate publishable.

For unsupported helpers, register a centralized `Frontend` rule. For nonstandard field selection use `WireCodec`; for custom wire types use `TypeMapper`. Preserve existing handler bodies, DTOs, and routes. Use `contracttest` with actual request/response samples to test the declared constraints; the compiler does not execute business functions to claim enforcement.

## Ownership and budgets

Capture is off by default. Enabling it does not change Bundle format, capability flags, generated bytes, or fingerprint inputs. Reporting options are removed from custom mapper and codec projection inputs. Querying does not rerun rules or reread files. Results contain no retained AST, Go type objects, or callbacks, and every query returns detached JSON-compatible data, including nested Schema and raw declaration values.

`MaxExplainBytes` limits additional serialized evidence to sixteen MiB by default; a positive value selects another limit. It does not count the existing immutable Bundle snapshot or limit the complete query response size. Exceeding the evidence budget fails compilation with `openapi.explain.budget`; no successful partial report is returned. Normal source and type graph budgets still apply. Explain queries require the original captured result and remain valid even if its exported Bundle field is replaced.

For standalone type projection, set `ProjectionRequest.Explain` to receive `Projection.Origins` and `Projection.Rules` during the existing projection. It uses the normal type-node budget and has no handler or response context. Separate `Project.Schema` calls remain independent and may run concurrently under the public read-only ownership contract.
